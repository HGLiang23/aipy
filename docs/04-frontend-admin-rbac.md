# 前端、系统管理与 RBAC 交互详细设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 首版详细设计基线 |
| 产品形态 | 面向小团队的 SaaS 内容生产平台 |
| 前端技术 | Next.js、TypeScript、TipTap |
| 核心对象 | 租户、工作空间、品牌、批次、内容任务、工作流节点、产物版本、人工任务、平台账号 |
| 支持平台 | 微信公众号、小红书；首版以预览和发布包导出为主 |
| 工作流模式 | 全自动、人机协同、全人工、自定义 |

本文只定义前端、系统管理及 RBAC 交互。工作流采用模板表单和节点列表配置，不建设拖拽式工作流编辑器。

## 2. 设计目标与原则

1. **自动化与人工控制使用同一套流程**：每个节点均可配置自动继续、自动后审核、人工处理、跳过或禁用；用户可选全自动预设，也可逐节点覆盖。
2. **权限由后端最终裁决**：前端根据权限渲染菜单和操作，但不得把隐藏按钮当作安全边界。
3. **业务阶段与执行状态分离**：页面同时展示内容处于哪个阶段，以及工作流是运行、等待人工、失败还是暂停。
4. **所有人工修改均形成新版本**：不覆盖 AI 原始产物；审批、发布、导出必须绑定明确版本。
5. **上游变更可追踪**：修改采集材料、选题、Brief 或大纲后，明确标记受影响的下游产物为 `STALE`，由用户决定重算或沿用。
6. **小团队优先**：减少后台层级和配置负担，提供安全默认值、角色模板和工作流预设；复杂能力按需展开。
7. **高风险动作显式确认**：自动发布、跨范围批量操作、覆盖人工内容、沿用过期产物、终止批次均需二次确认和审计理由。

## 3. 用户与管理域

### 3.1 两类后台边界

| 能力 | SaaS 平台后台 | 租户工作台/租户后台 |
| --- | --- | --- |
| 面向人员 | 平台超级管理员、平台运营、平台审计员 | 租户管理员、内容运营、编辑、审核员、发布员、分析员 |
| 租户管理 | 创建、冻结、恢复、查看套餐与全局用量 | 查看本租户信息，不可修改系统租户标识 |
| 套餐和硬配额 | 定义套餐上限、全局硬限制 | 在套餐范围内设置团队软/硬配额和告警阈值 |
| 模型供应商 | 注册供应商、模型目录、全局禁用、价格元数据 | 选择允许模型、配置平台密钥或 BYOK、节点路由与预算 |
| 采集安全 | 全局禁用域名、协议、私网访问和文件安全策略 | 配置本租户来源、域名白名单、关键词、频率和保留期 |
| 发布能力 | 控制允许的发布方式和平台接入能力 | 管理本租户平台账号、审批和导出/发布策略 |
| 用户与角色 | 平台后台人员权限 | 本租户用户、团队、角色、数据范围 |
| 工作流 | 系统内置模板、不可突破的安全约束 | 复制模板、配置节点执行模式、审批点和质量阈值 |
| 审计 | 跨租户安全事件；默认脱敏 | 本租户业务操作、审批、配置和导出记录 |
| 内容访问 | 默认无权查看租户正文；需授权的支持访问必须审计 | 按团队、品牌、任务归属和角色访问 |

平台人员不得因拥有平台管理权限而自动获得租户内容读取权限。需要支持排障时，使用限时授权、明确原因和完整审计。

### 3.2 租户内部层级

```text
租户
├── 工作空间（小团队首版默认一个，可预留多个）
│   ├── 团队
│   ├── 品牌
│   ├── 内容项目
│   ├── 采集来源
│   ├── 工作流模板
│   └── 平台账号
└── 用户、角色、配额、模型凭证、审计
```

首版 UI 不强迫用户理解多层组织：只有一个工作空间时隐藏工作空间切换器；只有一个品牌时自动选中，但数据模型仍保留对应标识。

平台后台和租户工作台使用独立路由前缀、导航框架和会话受众，例如 `/platform/*` 与 `/app/*`，避免平台权限和租户权限混用。

## 5. RBAC 与授权模型

### 5.1 授权判定

授权不是单纯的角色判断，统一由后端授权服务计算：

```text
allow = tenant_is_active
     AND user_is_active
     AND role_has(resource, action)
     AND data_scope_matches(resource)
     AND workflow_state_allows(action)
     AND resource_policy_allows(action)
     AND separation_of_duties_allows(action)
```

前端从会话和资源详情接口取得：

- `permissions`：当前用户的全局权限码集合。
- `allowed_actions`：针对当前资源和当前状态计算后的动作集合。
- `denial_reason`：不可操作原因，用于禁用态说明；不得泄露其他租户信息。
- `etag` 或 `version`：提交更新时用于乐观锁检查。

列表页只使用全局权限决定是否显示“新建”等操作；行级操作必须使用该行返回的 `allowed_actions`，不能由前端自行推导。

### 5.2 权限命名

采用 `resource:action`，首版至少包含：

```text
batch:view, batch:create, batch:start, batch:pause, batch:resume, batch:cancel
content:view, content:create, content:edit, content:assign, content:delete
artifact:view, artifact:edit, artifact:regenerate, artifact:lock, artifact:compare, artifact:restore
source:view, source:create, source:edit, source:delete, source:collect
workflow:view, workflow:configure, workflow:execute, workflow:override
review:view, review:claim, review:approve, review:reject, review:reassign
publication:view, publication:preview, publication:export, publication:publish, publication:withdraw
model:view, model:configure, model:credential_manage
quota:view, quota:configure
member:view, member:manage
role:view, role:manage
audit:view, audit:export
```

`workflow:override` 用于跳过可选节点、以 `STALE` 产物作为返工输入、超过软限制或改变正在运行任务的后续策略，不应默认授予普通编辑。它不能绕过硬性质量门禁、租户隔离或发布前的新鲜度检查。

### 5.3 租户角色模板与权限矩阵

| 权限领域 | 租户管理员 | 内容运营 | 编辑 | 审核员 | 发布员 | 数据分析员 | 只读访客 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 成员、角色、团队 | 管理 | 查看 | - | - | - | - | - |
| 品牌与业务配置 | 管理 | 管理 | 查看 | 查看 | 查看 | 查看 | 查看 |
| 批次与内容任务 | 管理 | 创建/管理 | 查看分配项 | 查看待审项 | 查看待发布项 | 查看 | 查看授权项 |
| 素材与采集 | 管理 | 管理 | 查看/补充 | 查看引用 | 查看 | 查看 | 查看授权项 |
| 选题、Brief、大纲 | 管理 | 编辑/提交 | 编辑分配项 | 审批 | 查看 | 查看 | 查看授权项 |
| 正文和平台版本 | 管理 | 编辑/提交 | 编辑分配项 | 审批/退回 | 只读 | 查看 | 查看授权项 |
| 工作流模板 | 管理 | 使用/复制 | 使用 | 查看 | 查看 | 查看 | - |
| 人工任务 | 全部 | 领取/转派 | 处理分配项 | 处理审核项 | 处理发布项 | - | - |
| 导出 | 管理 | 申请/执行 | 申请 | 审批 | 执行 | - | - |
| 自动发布 | 配置/执行 | 申请 | - | 审批 | 执行 | - | - |
| 模型、配额、发布配置 | 管理 | 查看 | - | - | 查看发布配置 | 查看用量 | - |
| 审计 | 查看 | 查看业务记录 | 查看本人相关 | 查看审核相关 | 查看发布相关 | 查看只读统计 | - |

模板用于快速初始化，租户管理员可以复制后定制。系统必须阻止删除最后一个有效租户管理员角色或移除最后一名租户管理员。

### 5.4 数据范围

角色绑定功能权限和数据范围，支持：

| 范围 | 含义 |
| --- | --- |
| `TENANT_ALL` | 本租户全部数据 |
| `TEAM` | 所属团队及明确授权团队 |
| `BRAND` | 指定品牌 |
| `ASSIGNED` | 分配给本人或本人当前领取的任务 |
| `CREATED_BY_ME` | 本人创建 |
| `CUSTOM` | 团队、品牌、项目、平台账号的组合 |

多个角色的功能权限取并集；数据范围也取允许范围的并集。显式资源封禁和租户隔离优先于角色允许。列表筛选、导出、统计聚合、全文检索都必须应用相同数据范围。

### 5.5 工作流状态授权

| 状态/阶段 | 运营 | 编辑 | 审核员 | 发布员 | 管理员 |
| --- | --- | --- | --- | --- | --- |
| `DRAFT` / 待启动 | 编辑配置、启动 | 编辑分配内容 | 查看 | 查看 | 全部 |
| `RUNNING` | 暂停、查看；有权时修改后续策略 | 处理人工节点 | 查看检查结果 | 查看 | 全部 |
| `WAITING_HUMAN` | 领取、转派 | 编辑类任务 | 审批类任务 | 发布确认任务 | 全部 |
| `PAUSED` | 恢复、调整后续策略 | 修改已授权产物 | 查看 | 查看 | 全部 |
| `FAILED` | 重试、转人工 | 修正产物 | 查看失败原因 | 查看发布失败 | 全部 |
| `COMPLETED` | 查看、复制为新任务 | 只读；新版本需创建修订 | 查看记录 | 导出/发布已批准版本 | 全部 |
| `CANCELLED` | 查看、复制 | 只读 | 只读 | 只读 | 删除归档前恢复 |

附加规则：

- 内容创建者默认不能审批自己提交的最终版本；小团队可由租户管理员显式开启“同人审批”，页面持续显示风险标识并写入审计。
- 审批只对提交时的版本有效。审批后正文、标题、图片、引用或平台版本发生变化，原审批自动失效。
- 发布员只能使用已批准且未 `STALE` 的版本。管理员可以将 `STALE` 版本作为返工输入，但不能直接导出或发布；必须先形成新的 `FRESH` 版本并重新通过门禁。
- 用户切换后续节点为全自动，不影响正在等待的当前人工任务；必须先处理或取消当前任务。

## 6. 工作流模板交互

### 6.1 预设模式

| 预设 | 行为 |
| --- | --- |
| 全自动 | 所有可自动节点为 `AUTO_CONTINUE`，遇到质量门禁失败或安全硬规则时转人工 |
| 人机协同 | 选题、大纲、最终平台版本默认 `AUTO_REVIEW`，其余自动继续 |
| 全人工 | 自动能力仅作为“建议生成”，主要节点为 `MANUAL` |
| 自定义 | 用户逐节点选择模式和审批规则 |

任何预设都不得绕过系统级安全硬规则、租户发布策略和套餐能力。

### 6.2 节点列表配置

工作流模板页面采用顺序节点列表，每行显示：

- 顺序号、节点名称、节点类型和简短说明。
- 执行模式：`AUTO_CONTINUE`、`AUTO_REVIEW`、`MANUAL`、`SKIP`、`DISABLED`。
- 负责人或候选角色。
- 超时、重试次数、质量阈值、失败转人工策略。
- 使用的模型路由、Prompt 版本和预算上限摘要。
- 节点输入和产物类型。

点击节点打开右侧配置面板。允许上下移动固定节点，但不允许自由连线；首版分支规则使用结构化表单表达，例如“质量分低于 80 转人工审核”。保存模板时做完整校验并展示影响摘要。

### 6.3 运行时控制

内容任务详情提供“后续执行策略”入口：

- 将未开始节点批量切换为全自动或人机协同。
- 单独修改未开始节点的执行模式。
- 暂停后修改当前节点配置并重试。
- 已完成节点保留原执行模式和版本，不追溯重跑。
- 正在执行的节点不允许直接改变模式，先申请取消或等待完成。

## 7. 核心页面与用户流程

### 7.1 登录与租户进入

1. 用户登录。
2. 只有一个租户时直接进入；多个租户时选择租户。
3. 检查租户状态、成员状态和会话权限版本。
4. 首次进入展示最小初始化清单：品牌、模型、来源、工作流模板；可以稍后完成非阻塞项。

### 7.2 概览

首屏面向重复运营工作，展示：

- 今日批次：运行中、等待人工、失败、已完成。
- 我的人工任务：待领取、即将超时、已退回。
- 配额：生成、采集、Token、成本和发布额度。
- 最近内容和待导出内容。
- 异常：模型不可用、采集失败、账号授权即将过期。

卡片只作为摘要入口，不在卡片内嵌套复杂表格。主要工作通过批次、任务和内容列表完成。

### 7.3 创建批次

采用三步表单：

1. **目标**：品牌、平台、内容数量、目标日期、主题或关键词。
2. **输入与流程**：选择已有来源/临时 URL/上传文件，选择工作流预设或模板。
3. **确认**：预计调用节点、人工停靠点、预算、配额占用、输出格式。

提交前展示配额预占结果。用户可保存草稿，也可“创建并启动”。无模型或来源权限时，在对应字段就地说明，不等提交后统一报错。

### 7.4 批次列表与监控

批次列表支持状态、品牌、创建人、时间、工作流模板筛选，列包括：

- 批次名称和编号。
- 总任务数及成功/运行/等待人工/失败数量。
- 总进度和当前最长耗时阶段。
- Token、成本和配额使用。
- 创建人、开始时间、预计完成时间。
- 行级允许动作。

批次详情采用“摘要 + 任务表 + 事件时间线”：

- 摘要区显示整体进度、吞吐、失败率、预算和并发情况。
- 任务表可按节点、状态、负责人、错误类型筛选，支持权限内批量暂停、重试、转人工和分配。
- 时间线展示启动、策略修改、限流、批量失败、恢复和完成事件。
- 失败汇总按可重试、配置错误、输入问题、外部平台问题分组。
- 自动刷新默认 10 秒，后台标签页降低频率；提供明确的“最后更新时间”。

批量操作必须先显示受影响数量、不可操作数量及原因，不允许部分失败后只提示笼统错误。

### 7.5 内容任务详情

页面采用稳定的三栏结构：

```text
左栏：工作流节点和状态
中栏：当前节点产物/编辑器
右栏：来源、检查、评论、版本与属性
```

- 左栏可折叠，显示完成、运行、等待、失败、`STALE`、跳过状态。
- 中栏根据节点产物切换表单、列表、TipTap 编辑器或平台预览。
- 右栏使用标签页，不同时展开所有辅助信息。
- 顶部固定显示内容标题、整体状态、负责人、保存状态和主要动作。

窄屏下三栏改为主内容加抽屉；节点导航为顶部选择器，不能让正文缩到不可编辑。

### 7.6 各节点人工介入

| 节点 | 主要人工操作 |
| --- | --- |
| 采集 | 添加/删除来源、编辑提取结果、合并重复项、设置信任等级、重新采集 |
| 分析 | 修改聚类、趋势结论、关键词、目标受众和风险标记 |
| 选题 | 新增、合并、淘汰、排序、调整评分和角度，批准入选题池 |
| Brief | 编辑目标、受众、观点、语气、篇幅、CTA、禁用表达和引用要求 |
| 大纲 | 调整章节顺序、增删章节、锁定章节、绑定来源 |
| 章节写作 | 编辑、局部重写、锁定、评论、恢复版本 |
| 检查 | 接受修复、忽略误报、退回指定章节、补充证据 |
| 平台适配 | 修改标题、摘要、正文、标签、封面文案和排版 |
| 导出 | 最终预览、选择格式、检查缺失资源、批准生成发布包 |

所有节点均提供“保存草稿”“提交并继续”“重新生成”“转交”“查看运行信息”。动作是否出现由 `allowed_actions` 决定。

## 8. 内容编辑器

### 8.1 编辑器组成

TipTap 编辑器以结构化章节为边界，支持：

- 标题、段落、列表、引用、链接、图片、分隔符和有限格式。
- 章节导航、折叠和顺序调整。
- 选中文本后执行改写、缩写、扩写、调整语气；结果先以差异建议展示，用户确认后应用。
- 章节级重新生成和锁定，锁定章节不会被后续自动生成覆盖。
- 自动保存、保存状态、离开保护和离线/断线提示。
- 评论、@成员、待处理建议。
- 引用标记和来源侧栏联动。

不允许模型直接覆写存在未保存人工修改的章节。生成任务启动前保存当前版本；生成返回时若版本已变化，以冲突方式展示，不自动合并。

### 8.2 文档结构约束

前端维护稳定 `section_id` 和内容块 ID。标题、摘要、章节、引用、平台元数据分别保存；HTML 仅作为渲染或导出结果，不作为唯一事实源。

对公众号和小红书分别维护平台变体，不直接修改内容母版。母版变化后，变体进入 `STALE`，平台页面提示重新适配。

## 9. 版本、引用与 STALE

### 9.1 版本对比

版本面板显示版本号、来源、创建人/模型、时间、基于哪些上游版本、审批状态和说明。支持：

- 文本行内差异和左右并排差异。
- 按章节筛选变化。
- AI 原稿与人工修改稿对比。
- 查看标题、引用、图片和平台元数据变化。
- 从旧版本创建新修订；不得直接把已审批版本静默覆盖。

恢复旧版本实际创建一个新版本，并记录 `restored_from_version_id`。

### 9.2 来源引用

来源侧栏显示：

- 来源标题、域名、抓取时间、作者/发布日期、可信等级。
- 原始快照与清洗后文本。
- 当前章节引用的证据片段。
- 来源是否已失效、被删除或存在版权/可信风险。

点击正文引用定位来源证据，点击来源片段反向高亮引用位置。用户修改提取文本时保留原始快照，并标识“人工修订材料”。导出时可选择参考资料列表样式。

### 9.3 STALE 提示与处理

当上游版本变化导致下游可能过期时：

- 左侧节点显示琥珀色 `STALE` 标识，不与失败状态混用。
- 页面顶部说明“哪一个上游版本发生了什么变化、哪些产物受影响”。
- 提供“重算全部受影响节点”“仅重算选中节点”“查看差异”“沿用旧结果”操作。
- 沿用旧结果需要 `workflow:override`，填写理由，并在审批和发布页持续显示风险。
- 已审批下游产物变为 `STALE` 时，审批自动失效。
- 人工锁定章节仍保留，但检查和平台适配可重新执行。

系统不得自动删除旧版本，也不得在后台无提示地覆盖人工内容。

## 10. 人工任务与审批

### 10.1 人工任务中心

提供“我的任务”“待领取”“团队任务”“已完成”标签页，支持按类型、优先级、截止时间、品牌、批次筛选。列表显示任务对象、产生原因、当前版本、候选角色、到期时间和允许动作。

任务能力包括：

- 领取、放弃领取、转派、委托、加签。
- 批准、驳回、要求修改、评论。
- 批量批准低风险同类任务；最终发布默认不支持无预览批量批准。
- 超时提醒和升级给团队管理员。
- 租户管理员查看队列负载并重新分配。

### 10.2 审批详情

审批页必须同时展示：

- 待审批的明确版本和上游版本。
- 与上次批准版本的差异。
- 来源引用、事实/合规/风格检查结果。
- 是否存在 `STALE`、模型降级、人工忽略检查项或预算超限。
- 平台最终预览和导出/发布目标。

批准和驳回均要求意见；租户可将低风险批准意见配置为选填。审批提交使用乐观锁，版本已变化时阻止提交并要求重新加载。

## 11. 配置页面

### 11.1 模型策略

租户管理员可配置：

- 使用平台托管凭证或 BYOK；密钥保存后只显示掩码和最后验证时间。
- 各节点的主要模型、备用模型、温度、最大输出、超时和预算。
- 数据处理区域、是否允许将数据发送给该供应商。
- 降级策略和“降级后必须人工审核”。
- 连接测试和结构化输出能力检查。

普通用户只看到模型名称和运行成本摘要，不看到密钥。删除正在使用的凭证前展示受影响模板和运行任务。

### 11.2 采集策略

采用来源列表和来源表单，支持人工 URL、RSS、文件上传。配置项包括域名范围、关键词、语言、抓取频率、单次上限、可信等级、保留期和是否需人工确认。

系统级禁用域名和安全规则只读展示原因，不允许租户覆盖。来源测试展示解析结果和错误，不把任意远程 HTML 直接注入后台页面。

### 11.3 配额与告警

展示套餐上限、租户限制、已用、预占、剩余和重置时间：

- 每日生成、发布、采集数量。
- 并发任务和单批次来源数。
- Token、日成本和单篇成本。

租户只能在套餐上限内配置软/硬限制及 80%、90%、100% 告警接收人。用量页面可追溯到批次、内容任务和模型调用，但费用数据按权限脱敏。

### 11.4 发布策略与平台账号

支持以下策略：

- `MANUAL_EXPORT`
- `APPROVAL_THEN_EXPORT`
- `APPROVAL_THEN_PUBLISH`
- `SCHEDULED_AFTER_APPROVAL`
- `FULL_AUTO`

页面明确展示当前平台账号实际具备的能力。选择不可用策略时禁用并说明原因。`FULL_AUTO` 配置需要额外确认质量阈值、审批豁免权限、失败转人工和发布额度。

平台账号页显示账号名称、平台、授权范围、授权状态、到期时间、最近同步和可操作团队；密钥或 Token 永不明文回显。

### 11.5 工作流模板

模板页提供系统模板、租户模板和使用中的版本。编辑时复制为草稿版本，发布后供新任务选择；运行中任务继续使用启动时快照。

模板校验至少覆盖：

- 必需输入和产物是否可达。
- 人工节点是否有候选角色。
- 模型和凭证是否可用。
- 自动发布是否满足租户安全策略。
- 节点预算之和是否超过批次上限。
- 跳过节点是否导致后续缺少输入。

## 12. 平台预览与发布包

### 12.1 微信公众号预览

按目标内容宽度渲染标题、作者、摘要、封面、正文图片、引用和链接。提示不支持样式、外链和资源缺失。预览旁显示正文结构和发布元数据，不用模拟完整微信客户端外壳。

### 12.2 小红书预览

显示标题长度、正文、标签、首图/图片序列和超限提示。桌面端并排显示编辑和移动端比例预览；移动端直接切换编辑/预览。

### 12.3 导出确认

导出前检查：

- 当前版本已批准且不为 `STALE`。
- 图片、链接和引用完整。
- 平台字段长度与格式符合规则。
- 用户具有目标品牌和平台账号的数据权限。
- 配额和导出策略允许。

发布包记录内容版本、平台变体版本、导出格式、操作者和校验结果。相同版本和格式重复导出可复用已有包，但每次下载仍写审计。

## 13. 审计交互

审计列表支持按操作者、资源、动作、时间、结果、IP、批次和内容任务筛选。详情展示：

- 谁在何时通过什么入口执行何种动作。
- 资源标识、租户、团队、请求追踪 ID。
- 修改前后差异；敏感字段只显示“已变更”。
- 审批意见、强制覆盖理由、导出和发布结果。
- 模型调用只引用调用记录，不在普通审计页暴露完整敏感 Prompt 或密钥。

审计日志只读，导出审计日志需要独立权限并记录二次审计。

## 14. 页面状态与反馈

### 14.1 加载状态

- 首次加载使用与实际布局一致的骨架屏，避免布局跳动。
- 长列表使用服务端分页或虚拟化；筛选和分页保留在 URL。
- 工作流运行使用轮询或服务端事件更新，显示最后更新时间和连接状态。
- 按钮提交后只锁定相关操作，不冻结整个页面。

### 14.2 空状态

空状态区分：无任何数据、筛选无结果、无权限看到数据、配置未完成。每种状态提供一个明确下一步，例如“创建首个批次”或“清除筛选”，不得用同一段笼统文案。

### 14.3 错误状态

- 表单错误定位到字段并保留用户输入。
- 节点失败展示用户可理解原因、错误分类、可否重试和追踪 ID。
- 批量操作返回逐项结果，成功项不回滚，失败项可筛选重试。
- `403`、`404`、租户冻结、配额耗尽、供应商不可用使用独立页面或明确横幅。
- 自动保存失败时持续警示并保留本地未提交内容，恢复后由用户确认重试。

### 14.4 冲突状态

所有编辑提交携带版本号或 `ETag`。服务器返回 `409` 时：

- 展示“你的版本”和“服务器最新版本”的差异。
- 支持复制本地内容、基于最新版本重新应用，或放弃本地修改。
- 不提供无提示强制覆盖。
- 审批和发布发生冲突时必须重新检查最新版本，不能直接重试旧请求。

### 14.5 危险操作

取消批次、删除来源、撤销批准、将 `STALE` 版本作为返工输入、启用全自动发布等操作使用确认对话框。确认内容说明影响范围；高风险操作要求输入原因，不用输入资源名称作为常规障碍。

## 15. 无障碍与响应式要求

### 15.1 无障碍

- 目标达到 WCAG 2.2 AA。
- 所有功能可通过键盘完成，焦点顺序与视觉顺序一致。
- 图标按钮具有可访问名称和可见 Tooltip；状态不只依赖颜色，同时使用文字和图标。
- 表单包含显式标签、帮助文本、字段级错误及错误摘要。
- 对话框打开后正确管理焦点，关闭后回到触发控件。
- 工作流进度更新使用非打扰式 live region；失败和冲突使用明确通知。
- 对比视图提供文本变化摘要，不只用红绿颜色。
- 正文编辑器支持键盘导航、标题层级和图片替代文本编辑。
- 尊重系统减少动态效果设置，避免持续闪烁和无必要动画。

### 15.2 响应式

- 主要目标是 1280px 以上桌面工作台；支持 768px 平板和 360px 手机查看/审批。
- 桌面三栏编辑器在平板改为双栏，在手机改为单栏加抽屉。
- 数据表在窄屏转换为关键字段列表，次要字段进入详情，不做不可读的横向压缩。
- 固定工具栏需预留内容空间，不遮挡编辑器、错误提示和底部操作。
- 批量复杂配置在手机端允许查看和简单审批；工作流模板深度配置提示使用桌面端，但不能阻断紧急暂停和驳回。

## 16. 前端工程约束

- Next.js 使用服务端会话校验和路由守卫；权限组件仅作为体验优化。
- 通过统一 `PermissionGate` 控制功能级显示，通过 API 返回的 `allowed_actions` 控制资源动作。
- 服务端状态使用统一查询层，查询键必须包含 `tenant_id`；切换租户时清空租户相关缓存。
- 表单使用共享 Schema，与后端错误码建立稳定映射。
- TipTap 文档转换、平台渲染和导出使用同一版本化转换规则，避免预览与导出不一致。
- 所有时间显示租户时区并保留原始 UTC；配额页明确重置时区。
- 权限、工作流状态、节点模式和错误码使用服务端字典或共享契约，不在页面散落字符串判断。
- 功能测试重点覆盖跨租户访问、状态越权、审批版本变化、并发编辑、`STALE` 传播和自动/人工模式切换。

## 17. 首版页面优先级

### P0：形成可用闭环

1. 登录、租户进入、基础导航和 `403/404`。
2. 租户成员、角色模板、功能权限和数据范围。
3. 品牌、基础模型凭证与节点模型策略。
4. 采集来源列表/表单、素材库和采集记录。
5. 工作流模板列表、预设选择和节点列表配置。
6. 创建批次、批次列表、批次详情和失败重试。
7. 内容任务详情、节点导航、TipTap 章节编辑器。
8. 来源引用、版本列表/对比、`STALE` 提示与重算。
9. 人工任务列表、领取、编辑、批准、驳回和转派。
10. 公众号/小红书预览、Markdown/HTML/ZIP 发布包导出。
11. 基础配额展示、操作审计、错误/加载/空/冲突状态。

### P1：提升批量运营效率

1. 批量任务分配、批量低风险审批、批次失败聚类。
2. 评论、@成员、审批委托、超时提醒和升级。
3. 模型成本明细、质量指标和人工修改比例。
4. 平台账号授权状态和官方接口能力探测。
5. 定时发布、审批后发布及发布失败转人工。
6. 工作流模板版本发布、影响分析和更完整的策略校验。
7. SaaS 平台租户、套餐、模型目录和全局配额后台。

### P2：规模化与企业增强

1. 企业 SSO、MFA、支持访问临时授权。
2. 双人审批、复杂加签和高级职责分离策略。
3. 多工作空间、企业租户独立数据存储选项。
4. 运营分析、实验对比和自定义报表。
5. 全自动发布的高级质量门禁和多平台扩展。

P0 中不包含拖拽式流程设计器、微前端、复杂主题定制和非官方浏览器自动发布。

## 18. 验收要点

1. 同一工作流模板可切换全自动、人机协同和逐节点自定义，且安全硬规则不可绕过。
2. 用户只能看到权限与数据范围内的菜单、列表和动作，直接调用接口同样被拒绝。
3. 人工修改任何产物都会创建版本；修改上游后能准确提示受影响的 `STALE` 产物。
4. 审批、导出和发布始终绑定明确版本，版本变化后旧审批失效。
5. 批次失败可以定位到单个内容任务和节点，并可单项或批量重试。
6. 编辑器不会静默覆盖人工内容，并能处理并发修改冲突。
7. 模型、采集、配额和发布策略在租户允许范围内可配置，密钥不可明文读取。
8. 微信公众号和小红书变体可分别编辑、预览和导出，并能追溯到内容母版版本。
9. 关键操作均可在审计日志中追溯操作者、版本、原因和结果。
10. 核心创建、编辑、审批和暂停流程可通过键盘完成，并在桌面、平板和手机上无内容遮挡。
