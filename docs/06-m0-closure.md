# M0 决策闭环

## 1. 首版平台交付契约

首版不把平台当前公开限制写死在领域层。每个发布连接器实现能力探测：

| 能力 | 含义 |
|---|---|
| `DRAFT` | 可创建或更新平台草稿 |
| `PUBLISH` | 可提交发布 |
| `SCHEDULE` | 可预约发布时间 |
| `STATUS_QUERY` | 可查询发布状态 |
| `WITHDRAW` | 可撤回或删除 |

账号能力在授权后实测并保存版本。能力不足时自动降级为
`MANUAL_EXPORT`，禁止使用浏览器自动化冒充官方接口。

统一发布包包含：

    manifest.json
    article.md
    article.html
    metadata.json
    citations.json
    assets/images/
    assets/covers/

`manifest.json` 固定租户、内容版本、平台变体版本、策略快照、生成时间、
文件哈希和导出格式。微信公众号与小红书的字段差异保存在各自
`metadata.json` Schema 中；具体长度和账号能力由连接器运行时规则校验，
不在核心领域代码中散落常量。

## 2. 模型供应商决策

首版最多启用两家文本模型供应商和一家 Embedding 供应商。系统管理员维护
允许目录，租户只能从目录中选择：

- 主要模型：选题、Brief、大纲和正文生成。
- 审核模型：事实、引用、风格和合规检查，默认不与主要模型共享判定。
- 降级模型：只处理允许降级的任务；降级输出必须重新经过质量门禁。
- Embedding：品牌资料和来源检索。

支持平台密钥和租户 BYOK。密钥仅保存密钥管理服务引用，不能进入数据库
明文字段、策略快照、日志、Outbox 或 Celery 参数。供应商选择必须记录
数据处理区域、内容留存政策、费用单位、超时和模型能力。

首批供应商名称由部署方在上线前根据合同、数据区域和账号可用性填写；
当前设计不伪造已签约供应商。

## 3. 数据区域和密钥

- 租户创建时固定 `data_region`，跨区域处理必须显式获批并审计。
- 首版每个租户只能使用与其数据区域兼容的模型和对象存储。
- 本地开发使用环境变量；预发布和生产使用 Vault 或云 KMS/Secret Manager。
- JWT 签名密钥、模型密钥和平台 Token 分离，支持独立轮换。
- 日志和 Trace 只保存密钥引用 ID，不保存密钥值。

## 4. 五个端到端验收场景

对应结构化样例位于 [tests/fixtures/e2e](../tests/fixtures/e2e/)。

1. `full_auto_export`：可信 RSS 素材自动生成公众号发布包。
2. `assisted_topic_review`：选题和大纲等待人工修改批准，随后自动完成。
3. `full_manual`：人工提交选题、Brief、大纲和正文，系统负责检查与导出。
4. `upstream_edit_stale`：来源修订后精确标记下游 `STALE`，阻止旧包导出。
5. `cross_tenant_denied`：跨租户 API、任务和资源访问全部默认拒绝并审计。

## 5. 仍需项目方提供

- 至少两个真实目标账号的官方接口能力测试结果。
- 品牌规范、禁用表达和实际内容样本。
- 100 条黄金内容集及业务评分，系统不会用合成内容冒充业务真值。
- 首批模型供应商合同、数据区域和费用信息。

这些外部输入不阻塞工程底座，但阻塞自动发布和 AI 质量门禁正式上线。
