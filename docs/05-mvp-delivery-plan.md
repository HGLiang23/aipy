# SaaS AI 内容生产系统 MVP 交付计划

## 1. 文档目标

本文定义小团队交付 SaaS 多租户 AI 内容生产系统首版（MVP）的范围、里程碑、质量门禁、部署运维和上线标准。

首版目标是在受控成本和风险下打通以下业务闭环：

```text
素材采集 -> 清洗分析 -> 选题 -> Brief -> 大纲 -> 分段写作
-> 质量检查 -> 人工审核（按配置）-> 公众号/小红书适配 -> 发布包导出
```

工作流须支持 `FULL_AUTO`、`ASSISTED`、`FULL_MANUAL`、`CUSTOM` 四种模式。租户管理员可配置每个节点为自动继续、自动后审核、人工处理、跳过或禁用；平台安全底线和套餐上限不可被租户配置覆盖。

## 2. 交付原则

- 架构采用模块化单体、独立异步 Worker、PostgreSQL、Redis 和对象存储。
- 业务数据以 PostgreSQL 为唯一事实来源；Redis 仅承担队列、锁、限流和短期缓存。
- 所有业务表强制包含 `tenant_id`，应用授权与 PostgreSQL RLS 共同保证租户隔离。
- 内容产物结构化、不可变版本化，并记录上游版本依赖；人工编辑不覆盖历史版本。
- 工作流启动时冻结配置、Prompt、模型路由和审批策略快照。
- 高风险操作后端强制鉴权；前端隐藏按钮不作为安全控制。
- 先支持发布包导出，平台官方发布接口经过权限和稳定性验证后再进入后续版本。

## 3. MVP 范围

### 3.1 In Scope

#### SaaS 与系统管理

- 租户、用户、团队、邀请、启停和基础套餐管理。
- RBAC 权限、数据范围、工作流阶段权限和集中式授权服务。
- 平台管理员与租户管理员两级管理后台。
- 租户级文章量、采集量、并发数、Token 和费用配额配置。
- 操作审计、登录日志、模型调用记录和成本台账。

#### 品牌与项目

- 一个租户可管理多个品牌、内容项目和平台账号档案。
- 品牌语气、目标受众、禁用表达、术语、默认篇幅和 CTA 配置。
- 品牌、项目、素材、Prompt 和模型凭据按租户隔离；项目级数据范围可授权。

#### 素材采集

- 人工录入、URL、RSS、文件上传三类来源。
- 批量采集、正文提取、清洗、去重、来源快照和可信度标记。
- 域名允许/禁止规则、采集频率、数量上限和来源保留策略。
- 人工增删、合并、修订和锁定素材；原始快照始终保留。
- URL SSRF 防护、文件类型/大小校验、恶意文件扫描接口和 HTML 清洗。

#### 内容生产工作流

- 批次任务和单篇内容任务；单篇失败不阻塞整批。
- 分析、选题、Brief、大纲、分段写作、合稿、引用检查、风格检查、合规检查和平台适配节点。
- 节点级自动执行、人工处理、审核、驳回、重跑、跳过、暂停和恢复。
- 上游版本变更后的下游失效标记，以及按影响范围重跑。
- 人工编辑锁定、乐观锁、版本对比、评论和审批意见。
- 失败重试、幂等键、并发限制、费用预算和人工重放。

#### AI 与模型治理

- 统一 `ModelGateway`，首版接入不超过两家文本模型供应商。
- 系统允许模型清单、租户模型路由、主备模型和平台密钥/BYOK 配置。
- Prompt、输出 Schema、模型参数和价格版本管理。
- 模型调用超时、限流、结构化输出校验、有限重试和受控降级。
- 每次调用记录租户、任务、模型、耗时、Token、估算费用和追踪 ID。

#### 审核、适配与导出

- 逐篇审核和批量查看；审批对象绑定不可变产物版本。
- 修改已审批版本后自动使审批失效。
- 公众号长文和小红书帖子独立适配，不共享最终正文。
- 发布前预览；导出 Markdown、HTML、JSON 和包含素材清单的 ZIP 发布包。
- 发布包包含正文、标题候选、摘要、标签、引用、图片和版权/来源说明。

#### 可观测性与运维

- 结构化日志、指标、链路追踪、错误聚合、告警和审计查询。
- 自动数据库备份、对象存储生命周期、恢复演练和密钥轮换流程。
- 开发、测试、预发布、生产环境及自动化 CI/CD。

### 3.2 Out of Scope

- Kubernetes、微服务拆分和服务网格。
- Temporal 或其他独立长周期业务编排平台。
- 可视化拖拽工作流设计器。
- 多 Agent 自由对话或自治团队。
- 全网搜索引擎式爬虫、绕过登录/验证码或平台反爬机制。
- 基于浏览器模拟的公众号或小红书自动发布。
- 未完成官方接口验证的全自动发布。
- 在线支付、自动开票和复杂订阅计费。
- 企业独立数据库、私有化部署和跨地域双活。
- 独立向量数据库；需要语义检索时首版使用 PostgreSQL `pgvector`。
- AI 视频生成和复杂图片编辑；首版仅支持图片上传、素材引用和可选封面提示词。

## 4. 容量与服务目标

容量是首版设计目标，不是初始承诺的无条件 SLA：

| 指标 | 目标 |
|---|---:|
| 活跃租户 | 20-50 |
| 单租户用户 | 5-20 |
| 全平台文章生成量 | 500 篇/日 |
| 同时活跃工作流 | 20-50 |
| 单批次文章数 | 100 |
| 单篇来源数 | 50 |
| 单篇工作流节点数 | 30 |
| 单文件上传大小 | 20 MB，可配置 |
| API 月可用性目标 | 99.5% |
| 普通 API P95 | <= 500 ms，不含 AI、采集和导出任务 |
| 异步任务入队 P95 | <= 1 s |
| RPO | <= 24 小时，目标 1 小时 |
| RTO | <= 4 小时 |

配额使用必须采用原子预占和最终结算，避免并发超额。达到并发上限时排队，不丢弃任务；达到硬配额时拒绝创建新任务并返回可解释错误。

## 5. 交付组织与节奏

### 5.1 推荐团队

最小可行团队为 5-7 人：

| 角色 | 建议投入 | 主要职责 |
|---|---:|---|
| 产品负责人/业务验收人 | 1 | 范围、优先级、工作流模板、验收签字 |
| 技术负责人/后端 | 1 | 架构、领域模型、授权、工作流和代码评审 |
| 后端工程师 | 1-2 | API、采集、异步任务、AI 网关、导出 |
| 前端工程师 | 1-2 | 运营工作台、编辑器、审核和系统管理 |
| AI/质量工程师 | 1 | Prompt、结构化输出、黄金集、模型评测和成本 |
| 测试/DevOps | 1，可兼职 | 自动化测试、CI/CD、环境、压测、恢复演练 |

产品负责人必须指定内容审核、安全和合规责任人。开发者不能自行放宽质量或发布门禁。

### 5.2 迭代节奏

- 总周期建议 10-12 周，采用两周一个 Sprint。
- 每周一次范围和风险评审；每日 15 分钟同步阻塞项。
- 每个 Sprint 第一天完成计划，最后一天完成演示、验收和回顾。
- 主干开发，短生命周期分支；合并必须经过评审和自动化门禁。
- 每个里程碑只在验收条件全部满足后关闭；遗留项显式进入风险或后续 Backlog。
- 从第二个 Sprint 开始，每周运行完整 AI 回归评测和一次预发布部署。

## 6. 里程碑与 Backlog

### M0：需求冻结与技术基线（第 1 周）

**依赖：** 无。

**Backlog：**

- 冻结 MVP In/Out Scope、术语、角色矩阵和默认工作流模板。
- 确认两个目标平台的发布包格式、内容规范和账号能力。
- 完成领域模型、ER 图、工作流状态机、产物依赖图和 API 约定。
- 确定首批模型供应商、成本基线、数据处理区域和密钥管理方式。
- 建立 100 条初始黄金样本，覆盖公众号、小红书、来源类型和风险类别。
- 建立威胁模型、数据分级、保留期限和日志脱敏规则。

**交付物：** MVP 规格、架构决策记录、ER 图、状态机、OpenAPI 草案、权限矩阵、初始黄金集、威胁模型。

**验收条件：**

- 产品、技术、质量负责人共同确认所有 P0 业务流程和异常路径。
- 每个工作流节点有输入、输出、执行模式、重试、权限和失效规则。
- 所有业务实体明确租户归属、版本策略和删除/保留策略。
- 至少用 5 个端到端案例走查全自动、人机协同和全人工模式。

### M1：工程底座与租户安全（第 2-3 周）

**依赖：** M0。

**Backlog：**

- 建立模块化单体、API、Worker、数据库迁移、Redis 和对象存储骨架。
- 实现租户、用户、团队、品牌、项目和基础套餐模型。
- 实现登录、Token 撤销、密码策略、RBAC、数据范围与集中授权服务。
- 为租户业务表启用 RLS，并建立自动化隔离测试。
- 实现审计日志、配置加密引用、请求追踪和基础管理后台。
- 建立开发/测试/预发布环境和基础 CI 流水线。

**交付物：** 可部署应用骨架、系统管理后台、数据库迁移、权限服务、审计与 CI。

**验收条件：**

- 两个测试租户的数据通过 API、后台任务和直接 SQL/RLS 均不可互访。
- 权限矩阵中的允许与拒绝案例 100% 自动化通过。
- 所有写操作产生含操作者、租户、资源、动作、时间和追踪 ID 的审计记录。
- 新环境可通过单条流水线命令完成部署和数据库迁移。
- P0/P1 安全扫描发现为 0。

### M2：采集与素材库闭环（第 3-4 周）

**依赖：** M1。

**Backlog：**

- 实现人工、URL、RSS 和文件采集连接器。
- 实现异步采集、正文提取、标准化、去重、来源快照和失败重放。
- 实现域名策略、SSRF 防护、HTML 清洗、文件校验和扫描适配器。
- 实现素材人工修订、锁定、合并、删除请求和版本对比。
- 实现采集配额、并发控制、来源审计和素材检索。

**交付物：** 素材库、三类采集连接器、采集任务页、安全控制和失败队列。

**验收条件：**

- 预定义的 URL、RSS、PDF/DOCX/TXT 样本均能生成可追溯来源快照。
- 重复样本识别率在验收数据集上 >= 95%，且支持人工纠正。
- 私网、环回、云元数据和重定向到受限地址的请求全部被阻断。
- 单连接器失败不阻塞批次，重放不会创建重复快照。
- 人工修改保留原始内容、差异、修改人和版本关系。

### M3：内容模型与可恢复工作流（第 4-6 周）

**依赖：** M1、M2 的素材版本契约。

**Backlog：**

- 实现批次、内容任务、节点运行、人工任务和状态转换。
- 实现结构化产物、不可变版本、依赖边和 `STALE` 传播。
- 实现 `FULL_AUTO`、`ASSISTED`、`FULL_MANUAL`、`CUSTOM` 模板。
- 实现节点暂停、恢复、取消、重跑、跳过、人工提交和审核。
- 实现幂等、有限重试、死信、并发限制、配额预占/结算和任务恢复。
- 冻结每次运行的工作流、模型、Prompt 和配额策略快照。

**交付物：** 工作流执行器、Worker、任务中心、人工任务箱、版本依赖服务。

**验收条件：**

- 四种模板各通过至少 3 个端到端状态机测试。
- Worker 在任意节点终止后可恢复，已完成节点不会产生重复副作用。
- 上游版本修改可准确标记受影响下游，未受影响章节保持有效。
- 两人并发编辑触发乐观锁冲突，不发生静默覆盖。
- 100 篇批次中单篇失败不会阻塞其余任务，可单篇重放和取消。

### M4：AI 生成、检查与治理（第 6-8 周）

**依赖：** M0 黄金集、M3 工作流与产物契约。

**Backlog：**

- 实现统一模型网关、两家供应商适配、主备路由和凭据管理。
- 实现分析、选题、Brief、大纲、分段写作、合稿节点。
- 实现引用、事实、重复度、品牌风格和合规检查节点。
- 对所有节点应用 Pydantic Schema 验证、输出修复和错误分类。
- 实现 Prompt/Schema 版本、调用日志、成本台账和租户预算门禁。
- 建立自动化离线 Eval、评测报告和变更对比。

**交付物：** ModelGateway、AI 节点、质量检查、Prompt 管理、成本页、Eval 流水线。

**验收条件：**

- 两家供应商均通过结构化输出契约测试，降级过程可审计。
- 初始黄金集全部执行，达到第 8 节定义的发布门禁。
- 单篇和单批次预算可阻断超额调用；费用误差不超过供应商账单的 5%。
- Prompt、模型或 Schema 变更未通过 Eval 时不能部署到生产。
- 不可信来源中的指令不会改变系统 Prompt、调用未授权工具或泄漏跨租户信息。

### M5：编辑审核、平台适配与导出（第 8-9 周）

**依赖：** M3、M4。

**Backlog：**

- 实现章节化富文本编辑、段落锁定、版本对比、评论和定向重写。
- 实现审核任务领取、转派、批准、驳回、撤回和超时提醒。
- 实现公众号和小红书独立适配、预览和格式校验。
- 实现 Markdown、HTML、JSON、ZIP 发布包及导出审计。
- 实现修改已审批版本后的审批失效和重新审核。

**交付物：** 内容工作台、审核任务箱、双平台预览、发布包生成器。

**验收条件：**

- 用户可在任意配置节点查看、编辑、重跑或人工提交，权限拒绝有清晰提示。
- 人工锁定章节在后续生成中不被覆盖。
- 发布包通过平台格式样例校验，引用和素材清单完整率 100%。
- 审批绑定具体版本；任何正文变化都会阻止旧审批版本导出。
- 同一内容母版可生成相互独立的公众号和小红书版本。

### M6：系统配置、配额与运营可观测性（第 9-10 周）

**依赖：** M1-M5。

**Backlog：**

- 完善租户套餐、配额、来源策略、模型路由和工作流模板配置。
- 实现配额使用、任务吞吐、费用、质量和人工修改率看板。
- 实现结构化日志、指标、追踪、错误聚合和告警路由。
- 实现管理员安全操作、配置版本、密钥轮换和审计查询。
- 补齐数据导出、租户停用和逻辑删除/异步清理流程。

**交付物：** 租户配置中心、运营看板、告警规则、审计检索和运维手册。

**验收条件：**

- 配置层级遵守系统 > 套餐 > 租户 > 项目 > 工作流 > 任务的约束。
- 运行中的工作流使用启动快照，不受后续配置修改影响。
- 配额阈值、任务失败、积压、成本异常和安全事件均可触发测试告警。
- 租户停用后用户无法登录、任务不再启动、数据按保留策略处理。

### M7：硬化、试运行与上线（第 10-12 周）

**依赖：** M1-M6 全部完成。

**Backlog：**

- 执行完整功能回归、AI Eval、容量、稳定性、安全和恢复测试。
- 修复全部 P0/P1 缺陷，评审可接受的 P2 遗留项。
- 完成生产部署、数据迁移、备份、告警、值班和回滚演练。
- 选择 3-5 个租户灰度试运行，持续至少 7 天。
- 完成用户培训、支持手册、隐私说明和故障沟通模板。

**交付物：** 测试报告、灰度报告、安全报告、恢复演练报告、上线/回滚 Runbook。

**验收条件：**

- 第 7-13 节所有门禁通过，P0/P1 缺陷为 0。
- 在设计容量下持续压测 2 小时，无数据错乱、跨租户访问或任务丢失。
- 灰度期无未解决 P0/P1 事故，关键工作流成功率 >= 98%。
- 完成数据库与对象存储恢复演练，满足 RPO/RTO。
- 产品、技术、安全、运维共同签署上线批准。

## 7. 测试金字塔

建议自动化测试数量比例：单元测试 60%-70%，模块/集成测试 20%-30%，端到端测试 10%-15%。AI Eval 独立于传统测试运行，但属于发布门禁。

### 7.1 单元测试

- 领域状态转换、权限策略、配额计算、版本依赖和失效传播。
- 内容 Schema、Prompt 参数、模型响应解析、费用计算和错误分类。
- URL 安全校验、HTML 清洗、去重算法和导出格式转换。
- 关键领域模块分支覆盖率 >= 90%，项目整体行覆盖率 >= 80%。

### 7.2 模块/集成测试

- PostgreSQL、RLS、Redis、对象存储、队列和模型适配器。
- 数据库事务、幂等、重试、死信、配额预占/结算和审计一致性。
- 第三方服务使用契约测试与录制样本；CI 默认不依赖真实外部网络。
- 数据库迁移同时测试从上一生产版本升级和全新安装。

### 7.3 端到端测试

- 四种工作流模式的主路径和失败路径。
- 多租户登录、采集、编辑、审核、导出和审计闭环。
- 浏览器覆盖 Chromium；核心运营页面覆盖桌面常用分辨率。
- 每次生产部署执行烟雾测试，夜间执行完整 E2E。

## 8. AI Eval 黄金集与发布门禁

### 8.1 黄金集结构

MVP 上线前不少于 200 个案例：

- 公众号长文 80，小红书帖子 80，跨平台改写 20，拒绝/安全案例 20。
- 覆盖不同品牌语气、行业、篇幅、中文表达、来源数量和冲突来源。
- 至少 20% 为高风险案例：事实冲突、缺失引用、诱导指令、敏感表达、版权和 PII。
- 每个案例包含固定输入、来源快照、期望结构、禁止项、评分量表和人工基准。
- 数据集版本化；训练/调优样本与最终门禁集隔离。

### 8.2 评测维度

- Schema 与格式通过率。
- 来源忠实度、事实准确率和引用覆盖率。
- 品牌风格、平台适配、可读性和内容完整性。
- 敏感内容/Prompt Injection 召回率和误报率。
- 重复内容比例、人工修改率、耗时和单篇成本。

### 8.3 MVP 门禁

| 指标 | 门禁 |
|---|---:|
| 结构化输出成功率（含一次修复） | >= 99% |
| 必需字段和平台格式通过率 | 100% |
| 有来源支撑的事实准确率 | >= 95% |
| 应引用陈述的引用覆盖率 | >= 95% |
| 高风险内容召回率 | >= 98% |
| Prompt Injection 防护通过率 | 100% |
| 品牌/平台人工评分 | 平均 >= 4/5，且无 1 分 |
| 相对基线质量回退 | 任一核心维度不得下降 > 3% |
| 单篇成本 | 不超过租户/任务预算 |

最终发布包仍由工作流配置决定是否需要人工审批。AI 评分不能替代依法需要的人工审核。任何模型、Prompt、Schema、检索或工作流变更必须跑受影响集；正式发布前跑完整门禁集。

## 9. 专项测试

### 9.1 性能与稳定性

- 以 50 个租户、500 篇/日、50 个同时活跃工作流构造混合负载。
- 持续压测 2 小时，另做 8 小时低强度稳定性测试。
- 验证 API P95、队列等待、Worker 利用率、数据库连接、模型限流和对象存储吞吐。
- 人为注入模型超时、429、Redis 短时不可用、Worker 崩溃和对象存储失败。
- 验收：无任务丢失/重复副作用；错误可重试或进入人工重放；恢复后积压可在 2 小时内清空。

### 9.2 安全

- SAST、依赖漏洞、镜像漏洞、密钥扫描和许可证检查。
- 登录暴力破解、Token 撤销、越权、IDOR、SQL 注入、XSS、CSRF、SSRF 和上传攻击。
- Prompt Injection、工具越权、敏感信息回显和日志泄漏测试。
- 验收：P0/P1 为 0；互联网暴露面不得存在已知可利用高危漏洞。

### 9.3 租户隔离

- 对每个核心资源执行跨租户读、写、搜索、导出、任务恢复和对象访问测试。
- 验证 API、Worker、缓存键、RLS、对象路径、模型日志、审计和后台报表。
- 使用随机租户/资源 ID 做属性测试，确保请求体中的 `tenant_id` 不被信任。
- 验收：跨租户成功访问为 0；所有拒绝均有安全审计记录。

### 9.4 恢复与一致性

- Worker 在每个节点执行前、执行中、写入后终止并恢复。
- 数据库备份恢复到隔离环境，并校验业务行数、租户边界和关键产物哈希。
- 验证 Redis 全量丢失后可从数据库恢复业务，不丢失事实数据。
- 模拟发布包生成中断、配额结算失败和对象写入失败。
- 验收：RPO <= 24 小时且目标达到 1 小时，RTO <= 4 小时；幂等测试无重复扣费和重复产物。

## 10. CI/CD、环境与部署

### 10.1 流水线

每次 Pull Request：

1. 格式、Lint、类型检查和数据库迁移静态检查。
2. 单元测试、模块测试、权限/隔离测试。
3. SAST、依赖、密钥和许可证扫描。
4. 构建不可变容器镜像并生成 SBOM。
5. 对 AI 相关变更运行受影响黄金集。

主干合并后：

1. 镜像签名并推送制品库。
2. 自动部署测试环境，执行迁移和 E2E。
3. 完整 AI Eval 通过后允许提升至预发布。
4. 生产部署须人工批准，采用滚动或蓝绿方式。
5. 部署后执行烟雾测试；失败自动停止并按 Runbook 回滚应用。

数据库迁移遵循 expand/migrate/contract，破坏性收缩至少延后一版，禁止把数据库回滚依赖于不可逆 DDL。

### 10.2 环境

| 环境 | 用途 | 数据要求 |
|---|---|---|
| Local | 单人开发 | 合成数据、容器化依赖 |
| Test | 自动化集成与 E2E | 每次可重建、无生产密钥 |
| Staging | 生产等价验收和压测 | 脱敏/合成数据、独立第三方凭据 |
| Production | 正式租户 | 最小权限、加密、审计、备份 |

环境配置由环境变量和 Secret Manager 注入。禁止在代码库、镜像或普通配置表保存明文凭据。

### 10.3 MVP 部署拓扑

- 反向代理/负载均衡器。
- 2 个 API 实例，支持滚动升级。
- 2 个通用 Worker，可按采集和 AI 队列分配并发。
- 托管或高可用 PostgreSQL，启用 PITR 条件下的连续归档。
- Redis 和兼容 S3 的对象存储。
- 单独的定时调度进程，使用分布式锁避免重复触发。

不引入 Kubernetes；使用托管容器服务或 Docker Compose 加主机编排脚本。部署方式必须支持实例重启、横向增加 Worker 和无状态 API 替换。

## 11. 监控与告警

### 11.1 核心指标

- API：请求量、P50/P95/P99、4xx/5xx、鉴权拒绝。
- 工作流：创建量、成功率、各节点耗时、重试、失败、人工等待和 `STALE` 数量。
- 队列：积压、最老消息年龄、消费速率、死信数量。
- AI：供应商成功率、429/5xx、首 Token/总耗时、Schema 失败、Token 和费用。
- 采集：成功率、被安全策略阻断数量、解析失败和重复率。
- 基础设施：CPU、内存、磁盘、数据库连接/锁/慢查询、Redis 内存和对象存储错误。
- 业务：租户配额、文章产量、导出成功率、人工修改率和质量门禁通过率。

### 11.2 初始告警阈值

- API 5xx 率 5 分钟 > 2%：P1；> 5%：P0。
- 核心工作流 15 分钟成功率 < 95%：P1。
- 队列最老任务等待 > 10 分钟或积压持续增长 15 分钟：P1。
- 模型供应商错误率 5 分钟 > 10%：切换降级并 P1 告警。
- 单租户小时费用超过日预算 50%：暂停其自动任务并通知。
- 跨租户访问检测、密钥泄漏或审计中断：立即 P0。
- 备份失败一次：P1；恢复校验失败：P0。

告警必须包含租户（允许时）、请求/任务 ID、影响范围、看板和 Runbook 链接，避免仅发送无法操作的错误文本。

## 12. 备份与恢复

- PostgreSQL 每日全量备份，并启用持续归档/PITR，保留 30 天。
- 对象存储启用版本控制；发布包和原始来源按租户保留策略管理。
- Redis 不作为业务备份对象，必须能从 PostgreSQL 重建。
- 配置、Prompt、工作流模板和审计数据纳入数据库备份。
- 密钥系统只备份密钥引用和恢复流程，不导出明文到普通备份。
- 每周自动执行备份完整性校验；每月至少一次恢复到隔离环境。
- 上线前和每季度执行一次完整灾难恢复演练，记录实际 RPO/RTO。
- 恢复后验证租户总数、核心表数量、RLS、随机产物哈希、对象引用和审计连续性。

## 13. 风险与降级方案

| 风险 | 预防/监测 | 降级方案 |
|---|---|---|
| 模型供应商不可用或限流 | 主备路由、超时、熔断、健康指标 | 切换备用模型；暂停自动流程并进入人工任务箱 |
| 模型质量回退 | 黄金集、版本固定、线上抽检 | 回滚模型/Prompt；高风险内容强制人工审核 |
| 成本异常 | 预算预占、租户限额、费用告警 | 禁止新 AI 调用；允许人工编辑和已生成内容导出 |
| 队列积压 | 并发指标、最老任务告警 | 暂停低优先级采集；增加 Worker；限制新批次 |
| 采集目标封禁或内容变更 | 连接器隔离、错误分类、契约样本 | 禁用故障连接器；转人工 URL/文件录入 |
| 恶意网页/Prompt Injection | 内容隔离、安全规则、红队集 | 隔离来源；禁止工具调用；转人工审查 |
| 跨租户数据泄漏 | RLS、集中授权、隔离测试和告警 | 立即封禁相关路径/租户，轮换密钥，按预案调查和通知 |
| 数据库故障 | 高可用、PITR、连接监控 | 系统切只读/暂停任务，恢复数据库后重放安全任务 |
| Redis 丢失 | 无事实数据存储、幂等设计 | 暂停调度，重建缓存/锁，按数据库状态恢复任务 |
| 对象存储故障 | 重试、校验和、版本控制 | 暂停采集/导出，正文编辑保持可用，恢复后补写对象 |
| 重复执行/重复计费 | 幂等键、唯一约束、费用流水 | 阻断任务，按台账冲正，人工重放指定节点 |
| 审批绕过 | 后端状态权限、版本绑定、审计 | 禁止导出，撤销受影响包，强制重新审批 |
| 人员不足或进度延期 | 严格 In/Out Scope、每周风险评审 | 先保留单来源、单模型和 Assisted 模板，延后次要管理报表 |

最低可用降级顺序：暂停自动采集 -> 禁用备用之外的模型 -> 关闭批量生成 -> 强制人工审核 -> 仅保留人工编辑与发布包导出。任何降级不得关闭租户隔离、审计、幂等和审批版本校验。

## 15. MVP 完成定义

MVP 只有在以下条件同时满足时才算完成：

1. 3-5 个灰度租户能够独立完成从采集到发布包导出的闭环。
2. 同一工作流可由配置实现全自动、人机协同和全人工执行。
3. 所有内容产物可追溯到来源、上游版本、模型/Prompt 和人工操作。
4. 租户隔离、权限、审计、预算和审批门禁不能被前端或 Worker 绕过。
5. 设计容量、AI 质量、安全和恢复测试达到本文门禁。
6. 系统在外部模型或采集服务故障时可以安全降级，人工编辑和历史内容不受影响。
7. 上线清单全部关闭，并由产品、技术、质量和运维共同批准。
