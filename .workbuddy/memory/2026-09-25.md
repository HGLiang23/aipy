## 关键决策与坑
- **写接口不要传 `ResourceContext.workflow_state`**：`AuthorizationService._workflow_state_allowed`
  规定「该权限没配状态规则时资源不得带状态」，否则一律 `WORKFLOW_STATE_DENIED`；
  当前无策略源填充 `workflow_state_policies`，传了会造成「按钮可点、调用 403」。
  状态合法性改由状态机守卫。
- **`op.create_check_constraint` 的名字要传最终名**（`op.f("ck_<table>_xxx")`）：
  naming_convention 会再加 `ck_%(table_name)s_` 前缀，写成 `ck_content_run_ck_content_run_...`。
- `With` 校验迁移 0007 这类 ALTER：比对 `ADD COLUMN (\w+)`、`ADD CONSTRAINT (\w+)`、
  `COMMENT ON COLUMN` 与 ORM 的 `column.comment`，不要拿 CreateTable 全表 DDL 做对称差。
- HumanTask 模型**没有** `updated_at_label` 列（只有 ContentRun/Material 有）。

## 迁移与验证经验（重要）
- **约束名必须遵循 `NAMING_CONVENTION`**：`ck_<table>_<constraint_name>`、
  多列唯一约束把列名全拼（`uq_role_tenant_id_id`）、`fk_<table>_tenant_id_tenant`。
  手工写迁移极易漏掉 `TenantScopedMixin` 自带的 `tenant_id → tenant.id` 外键。
- **无数据库也能验证迁移零漂移**：把 ORM `Base.metadata` 的 `CreateTable/CreateIndex`
  用 `postgresql.dialect()` 编译，与 `alembic upgrade <rev>:head --sql`（offline）输出做
  「约束名 / 索引名 / COMMENT 文本」集合对称差比较，差集为空即无漂移。
- 编译 ORM DDL 前要先 import `tenancy.models`（否则 `tenant` 表缺失报 NoReferencedTableError）；
  SQLAlchemy 编译的 CreateTable **不带 COMMENT**，注释要从 `table.comment` / `column.comment` 取。
